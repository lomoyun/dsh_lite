# 对话操作插件

由 Agent 判断一段讨论是否适合进入下一步，通过 `propose_conversation_action` 提出建议，聊天页以蓝色下划线文字显示入口。
点击入口在右侧展示用途、理由与确认按钮；只有用户点击卡片确认，后台才调用执行器。
`extract_table` 显示名称为“整理参数表”，与阅读、解释已上传附件区分；设计调整尚未注册为可执行操作。

## 结构

- `src/actions.js`：应用内插件注册表和原生 DSH 工具注册，提出建议与执行分离。
- `src/action-plugins.js`：内置插件集合。工具名称、说明和可选操作从注册表生成。
- `src/action-history.js`：从原生工具结果恢复建议，从插件来源消息恢复确认状态。助手或用户的普通文字不能伪造状态。
- `src/runtime.js`：限定当前 Web 会话，提供原模型校验、执行上下文和原生日志刷新。
- `public/conversation-actions.js`：统一建议链接、详情卡片、确认/拒绝按钮与状态。新增同类插件不需要单独编写按钮。

沿用当前单 Agent、Cordis 和原生工具机制；没有新建 Agent、数据库、工作区元数据格式或根配置。
本版 SDK 不支持通过 `session.append()` 为外部自定义事件设置 `ignorable`，因此状态采用它支持的 `user/message`，
`source.kind=plugin`、`source.plugin=conversation-actions`、`form=notice`，供模型理解已作出的选择并支持日志恢复。

## 注册

在 `registerActionPlugins(actions)` 中注册下列字段。启动时安装，新增注册后重启服务生效。

| 字段 | 职责 |
| --- | --- |
| `id` | 稳定、唯一的操作名称，例如 `extract_table` |
| `title` / `confirmLabel` | 用户看到的标题与确认按钮文案 |
| `description` | 告诉 Agent 什么情形适合提出此操作 |
| `effect` | 向用户说明确认后会生成或改变什么 |
| `prepare(context)` | 执行前检查模型、业务输入和约束；失败时保留待确认状态 |
| `execute(context)` | 已确认之后执行；返回当前聊天响应格式的结果 |

上下文包含 `agent`、`action`、`requireModel()`、`run()`、`flush()`。
`run()` 使用当前会话和固定模型，表格插件使用内部提取指令，保留先前讨论。
第一版建议参数只有操作 ID 和理由，不接受模型传入任意代码、路径或待修改的设计参数。
注册的是受信任的后端代码。操作语义发生不兼容变化时应使用新的 ID，避免旧确认卡片执行不同含义的操作。

未来设计调整插件应先实现正式参数、固定工况和可制造性校验，并提供待确认的具体调整内容；
本版的通用注册入口不代表设计优化或 DLL 计算已经可用。

## 执行边界

1. 提议工具仅在 Web 聊天的当前轮可用，每轮至多一项；提取执行轮不再产生操作建议。
2. 建议工具只生成待确认信息，不进入执行器。何时建议由模型判断，不使用关键词或固定轮数作为生产触发器。
3. 确认必须引用该会话中真实存在且仍待处理的建议。新用户消息让旧建议失效；拒绝不额外调用模型。
4. 校验通过后，先记录并刷新执行中状态，再进入执行器；无法保存确认状态时不执行。
5. 已完成、已拒绝、已失败、已过时的建议不可重复执行。中断留下的执行中状态也不会自动重试。
6. 页面有待发送文字、表格修改或附件时，先处理这些内容，再确认建议。确认建议不会顺带发送这些草稿。
7. 表格提取结果还需核对；操作完成不代表满足 DLL 的正式计算输入条件。

这是一版基于会话内容的操作卡片插件机制，未提供第三方插件上传、动态安装或任意表单参数编辑器。
