# Excel 理解插件设计

## 1. 目标与架构

新增独立 DSH 插件 `excel-understanding`，提供**工作簿读取、按需查阅、视觉核验、理解结果及来源追溯**。当前 Agent 调用插件完成理解，同一份结果用于当前页面展示，并预留返回上游对话 Agent 的接口。

借鉴 Codex 可观察到的工具使用方式：**先检查文件，再按需读取、分析、回查证据，最后回答**。不把未公开的 Codex 内部实现作为设计依据。

```text
对话附件 → 保存原文件 → 工作簿结构解析
                            ↓
                  当前 Agent 获取全局概览
                            ↓
                  读取区域／搜索／查看预览
                            ↓
                   理解结果＋证据校验
                      ↙           ↘
                当前对话页面     未来 A2A 适配器
```

保留现有 DSH Agent 循环、模型配置及对话功能，调整附件处理、工具注册和详情展示，无需重写 Agent 架构。

## 2. 插件内部设计

采用三层处理，明确区分原始事实、视觉观察和模型推断。

| 层次 | 技术与职责 |
|---|---|
| 结构读取 | SheetJS 读取 XLSX、XLS、CSV；保留所有 Sheet、坐标、原始值、显示值、公式、合并区域及隐藏状态 |
| 布局与对象 | XLSX 补充读取 OOXML 元数据，识别图片、批注、绘图锚点和可识别的勾选信息；Linux 使用 LibreOffice＋Poppler 生成 PDF、区域图片 |
| 语义理解 | 当前对话模型结合结构和预览，识别表单区域、字段、单位、填写值、缺项和冲突，并引用来源 |

SheetJS 本身能提供原始值、格式化值、公式和合并区域；现有统一转换丢失了其中一部分信息，应先修正信息保留方式。[单元格结构](https://docs.sheetjs.com/docs/csf/cell/)、[合并区域](https://docs.sheetjs.com/docs/csf/features/merges/)

具体规则：

- 遍历全部 Sheet，包括隐藏页；先生成目录和内容概览，再按区域读取，避免把整个工作簿一次塞入上下文。
- 保留原始空白和合并关系，不再默认“第一行就是表头”。
- 公式表达式、缓存结果、显示文本分别保存。预览转换可能发生重算，其结果不得覆盖原始解析数据。
- 预览在隔离进程中生成，禁用宏和外部链接更新，设置时间、内存和输出大小限制。LibreOffice 支持 Linux 命令行 PDF 导出。[官方文档](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html)
- 当前模型支持图片输入时，通过 DSH 图片附件机制进行视觉核验；不支持时继续结构理解，将相关内容标记为“未完成视觉核验”，不自动切换模型。
- 不支持的控件、无法确认的勾选状态、解析或渲染失败必须显式列出。

## 3. 工具接口与结果契约

插件注册以下工具，供当前 Agent 在同一轮或后续对话中反复调用：

| 工具 | 作用 |
|---|---|
| `excel_inspect` | 返回文件信息、全部 Sheet、内容区域、对象和读取限制 |
| `excel_read_range` | 按 Sheet 和坐标范围读取单元格及关联元数据 |
| `excel_search` | 跨 Sheet 搜索字段、数值或说明，返回位置 |
| `excel_preview` | 获取 Sheet 或指定区域的预览及图片引用 |
| `excel_publish_understanding` | 校验并保存 Agent 整理的理解结果，返回展示用结果 ID |

发布结果包含：

- **工作簿概览**：文件包含什么，各 Sheet 用途及关联。
- **逐 Sheet 覆盖情况**：已索引、已读取、已理解和视觉核验范围。
- **内容与字段候选**：原文、解释、原始值、规范化候选值、单位。
- **证据**：文件 ID、Sheet、单元格范围或图片区域。
- **问题**：空缺、歧义、冲突、不支持内容和未检查区域。

程序校验证据坐标有效、原文与来源一致、规范化转换可追溯；它不将模型判断当作已经证明的事实。不确定项保留原值并提示核对。

“解析这个 Excel”直接启动读取和理解，不再只推送“确认提取”卡片。将理解结果应用到正式参数表，继续使用独立的用户确认动作。正式模板未确定前，不凭星号或模型猜测计算最终必填参数数量。

## 4. 存储、页面与 A2A 边界

- 原文件、解析索引、预览和理解结果按会话长期保存在插件管理的本地目录，Linux 部署挂载持久化卷；刷新、重启后可继续查阅。
- 使用不可变文件 ID、内容摘要和会话归属校验。同名文件分别保存，显式删除附件时清理关联产物。
- `lite-web-app` 负责附件入口和显示；解析逻辑迁入独立插件。保留“＋附件、拖入、发送时上传”的交互。
- 新附件向模型传递文件引用和简要目录；旧对话中的表格 JSON 继续可读，但没有原文件时明确限制回查能力。
- 对话主体只流式展示文字；蓝色下划线链接打开右侧详情，提供“概览、Sheet 内容、原始预览、待核对项”。
- 前端沿用现有原生 JavaScript，以分页单元格视图展示数据，PDF.js 展示布局预览；点击字段来源定位对应区域，无需引入完整在线 Excel 编辑器。
- 结果使用带版本的 JSON 和逻辑文件引用，不绑定 DOM 或 Windows 路径。未来 A2A 适配器将其映射为任务结果和文件产物，本期不实现 A2A 服务、鉴权或远程传输。[A2A 任务与产物概念](https://a2a-protocol.org/latest/topics/key-concepts/)

## 5. 验收与实施顺序

先固定结构和证据契约，再完成解析及持久化、Linux 预览、Agent 工具循环，最后接入右侧展示。

验收使用通用测试工作簿，并加入真实冷凝器、蒸发器客户输入表作为人工标注样例：

- 多 Sheet、隐藏页、多区域、合并表头、空白、公式、单位、小数逗号、前导零均有明确预期；结构读取与标注逐项一致。
- 图片、勾选框和复杂布局必须给出识别结果或待核对状态，不能静默遗漏。
- 样例中的关键参数必须值与来源同时正确；歧义不擅自修正，缺项不补造。
- 大表按需读取，达到限制时返回已覆盖范围和未处理内容，不声称完整解析。
- 实测当前模型的图片输入链路；分别验证支持视觉、不支持视觉及渲染失败的反馈。
- 验证连续追问、跨 Sheet 回查、重启恢复、同名附件隔离、删除清理，以及 Linux 后端与浏览器完整流程。

本期完成通用 Excel 理解插件和当前页面闭环；不包含原工作簿编辑、独立解析模型、A2A 部署或 DLL 计算。理解结果经过正式字段映射和输入校验后，才能成为计算输入。
