# MCHE 实际计算插件方案

## 1. 目标与首版范围

在现有 `@dsh-lite/mche` 插件中补齐计算能力，保留当前 Agent 循环和扁管、翅片、冷媒选型工具，实现：

**选择并确认部件 → 补充工况及工程参数 → 校验和映射 → 调用 DLL → 查看、追溯计算结果。**

已确定的首版范围：

- 使用 `CalcCondenser`，限定**单排、单流程、冷媒 PTM 边界**，即给定入口压力、温度和质量流量。
- 空气侧采用入口压力、干球温度、相对湿度和体积流量；采用均匀空气场和均匀冷媒分配。
- **页面点击和明确的对话指令都能触发计算**，共用同一个后端执行服务。
- 全部目录继续可以查询和选择；只对映射已验证的组合开放计算。
- 提供工程核对入口，补充目录缺少的信息，保存依据，不修改目录原值。
- 首版不包含蒸发器、多流程、多排、非均匀场、出口目标反算和自动优化。

## 2. S1—S2：Profile、工程输入和映射

### S1：建立原生契约与计算 Profile

建立 `mche.condenser.single_row.ptm.v1`。Profile 定义支持条件、必填字段、模型设置、映射版本及验收证据；不预填用户工况或示例几何。

原生契约依据已核对的 `dll.h`、`index.h`、实际调用代码建立，覆盖全部 42 个参数，并明确：

- 数组位置、单位、枚举、矩阵尺寸以及输入输出方向。
- 原调用方采用的容量：General 16、Tube 70、Fin 50、Refrigerant 15、Air 8、Correlation 12、Dehumidification 3、Residual 12、Result 64；`Res5` 实际使用 6 项，`FanCoe7` 实际使用 10 项。
- 未使用的槽位、空指针和哨兵值逐项登记适用条件；禁止统一补零掩盖缺项。
- 按当前 DLL 哈希绑定契约及求解配置，版本变化后重新验证。

Mapper 使用确定性代码生成数组、矩阵和单位换算；Profile 不执行任意表达式。

### S2：连接现有选择快照与计算输入

在现有方案中新增独立的 `calculation` 子状态，保存计算草稿、确认记录、工程补充和准备结果。旧会话读取时补空状态，保留原选择及历史快照。

| 输入来源 | 计算所需内容 |
|---|---|
| 扁管快照 | 管宽、管高、孔数、孔尺寸及相关原表证据 |
| 翅片快照 | 厚度、宽度、高度、片距、开窗尺寸及原表证据 |
| 冷媒快照 | 精确标识、浓度和质量/体积基准 |
| 工况输入 | 冷媒入口绝对压力、温度、质量流量；空气压力、干球温度、相对湿度、体积流量 |
| 结构输入 | 管数、长度及带翅片/无翅片长度含义、冷媒入口方向、空气流向 |
| 工程补充 | 孔型表达、翅片尺寸对应关系、FPI 定义、材料导热系数及必要的装配说明 |

工程核对页展示“原表值 → 计算采用值 → 单位/换算 → 依据”。补充记录绑定部件快照和映射版本；更换相关部件后重新核对。模型可以整理草稿，不能代替用户确认。

关键映射规则：

- `tubePitch` 不映射到 `IN_TUBE_P`，后者是扁管周长；设计压力不替代冷媒入口压力。
- 不根据孔宽和孔高自动认定矩形孔，也不覆盖目录已有流通面积。
- 翅片焊前/焊后高度、Width/Depth、Full/Overall 开窗长度分别核对。FPI 换算必须明确使用节距还是净间距，不能一律使用 `25.4 / 片距`。
- `cRef` 及数值兼容槽使用经验证的物性绑定；Excel 序号不作 DLL 编码。EG/PG 浓度表达未验证时阻塞。
- 单流程连接矩阵由管数和明确方向生成，不要求用户填写原生矩阵。
- 校验只要求当前 Profile 使用的字段；未使用字段保留原文和提示，不因无关缺项阻塞计算。

参数准备保留现有逻辑几何展示，新增原生入参预览、逐字段来源和阻塞原因。只有输入已确认、映射完整且运行环境可用时，`calculationReady` 才为真。

## 3. S3—S4：计算工具、执行层和页面

### S3：提供计算工具

计算能力继续放在现有 MCHE 插件中，不增加独立 Web 服务或 MCP 服务。

| 工具 | 行为 |
|---|---|
| `mche_calculation_profile_get` | 返回首版能力、所需输入、当前缺项和支持限制 |
| `mche_calculation_update_draft` | 保存用户明确提供的工况及工程补充草稿 |
| `mche_prepare_calculation`（扩展） | 从确认快照生成原生参数包、来源和可计算状态 |
| `mche_calculate` | 接收准备包 ID，创建异步计算任务并返回 `runId` |
| `mche_calculation_get` | 查询任务状态、结果摘要及详细结果入口 |
| `mche_calculation_cancel` | 取消排队任务或停止本次计算进程 |

同源 HTTP 接口调用相同业务方法，另提供用户专用的计算输入确认接口。模型工具不接收 DLL 路径、任意位置数组或伪造的确认标记。

两种触发方式：

- **按钮触发：**用户在计算卡片点击“开始计算”，直接创建任务，无需模型在线。
- **对话触发：**Agent 根据本轮用户明确的计算指令调用工具，记录实际用户消息作为触发来源；附件、引用文本和插件提示不产生执行授权。

两种入口都检查当前会话、输入确认和准备包是否过期。“修改参数并计算”若产生未确认草稿，应返回待核对项，不绕过确认。

同一触发请求只生成一个任务；重试返回原 `runId`。准备包按计算相关输入、快照及规则摘要判定过期，普通查询不使其失效。

### S4：实现独立 x86 Worker 与结果界面

- Node 后端通过受控子进程和 JSONL 调用 x86 Python Worker；复用已存在的 ctypes 绑定与缓冲区管理方式，不引入旧项目的 Agent、FastAPI 或数据库层。
- 使用项目专用的解释器和运行目录。启动前检查位数、DLL/物性资源、哈希和实际 SHDLL 加载位置；不改动外部旧解释器的 junction。
- Worker 再次验证类型、长度、矩阵和有限数值，拒绝超出首版范围的参数。
- 全局串行执行原生计算；每次调用使用独立进程。默认运行超时 120 秒，可在插件配置中调整；取消后先请求停止，2 秒未退出则终止本任务进程。
- 任务持久化后立即返回，计算不占住聊天请求。保存排队、运行、成功、失败、取消、超时和中断状态；服务异常重启后将未完成任务标记为中断，不自动重跑。
- 每次运行保存确认输入、目录快照引用、Profile/Mapper/DLL 版本、完整原生入参、原始输出、错误、日志和耗时。

右侧详情增加“计算工况、工程核对、参数准备、计算结果”视图。页面可查看进度、取消和刷新恢复；结果包括换热量、出口状态、冷媒流量及空气/冷媒压降。

原始结果与展示换算分开保存。方案在运行期间改变时，结果仍归属于原输入快照，并标记为历史方案结果；不覆盖新方案状态。Agent 每轮获得最新任务摘要，完整数组和日志通过详情查看。

## 4. S5：测试与验收

必须同时完成自动校验、真实原生调用和浏览器交互验收：

- **映射测试：**验证数组位置、矩阵、长度/压力/温度/流量换算；覆盖负摄氏温度、0% 湿度、绝对压力、角度及 FPI 单位；验证净间距与节距不能混用。
- **数据边界：**未知孔型、未确认工程补充、EG/PG 映射缺失、非首版模式均明确阻塞；无关目录字段不被补零或强制作为必填。
- **状态与权限：**确认失效、跨会话访问、旧准备包、重复点击、对话和按钮并发触发、运行中修改方案，均有定向测试。
- **Worker：**验证实际 x86 环境，覆盖缺依赖、超时、崩溃、取消、非有限结果和服务重启；模拟 Worker 仅用于故障测试。
- **真实计算：**先用既有 LTR 输入核对原生绑定，再用至少一套“当前目录选型＋已确认工程补充＋PTM 工况”完成真实 DLL 调用，逐项核对最终入参，并用独立示例调用结果作对照。不能只回放旧样例就宣称目录计算已接通。
- **页面与回归：**分别验证点击和对话触发、缺项核对、结果展示及刷新恢复；运行现有选型、目录和会话相关测试，单独记录既有间歇性 502。

验收报告区分“接口与数值回归通过”和“工程精度验证”。旧软件保存结果存在版本差异时，不直接作为当前 DLL 的精度基准。真实目录组合所需的工程确认资料缺失时，保留为明确的数据验收阻塞，不以模拟结果代替。

本方案实施后，交付的是能从当前选型方案执行真实计算、展示结果并完整追溯输入的 MCHE 插件；未经验证的组合仍保留选型能力和明确的计算限制。
