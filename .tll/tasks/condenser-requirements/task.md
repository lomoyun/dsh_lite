## 用户提供的实施方案（原文）

### 1. 流程与提取范围

读取 Excel，依据表内标题和字段结构识别冷凝器需求表；不依赖文件名或固定位置。

只将有实际填写值的字段纳入提取结果。空白字段不生成填写记录；零、否定回答和带疑问的非空原文保留。字段保存原名、原始值、显示值、单位候选及来源；疑问和未核验内容明确标记。参考文件当前的 26 条记录作为读表验收样例。

右侧填写入口覆盖整份客户需求中的已填内容。后续计算所需的缺项，在独立补填区提供。

### 2. Boundary 与填写

Agent 根据已填内容推荐模式、说明依据及备选，用户选择确认。

冷媒覆盖入口 P&T&M、入口 P&X&M、入口 P&T＋出口 SC/T、入口 Tsat&SH&M、入口 Tsat&SH＋出口 SC/T；空气覆盖三种状态输入及体积流量／风速选择。

每次计算只采用一套明确输入。切换模式时保留已有值，重新标明计算输入、设计目标、参考信息及计算缺项。主工况和测试条件分别保留。

自动处理明确的数字格式、百分比及单位换算；工程公式和物性推算所需缺项由用户补填。目标换热量、空间尺寸、空气夹角不自动替代其他计算参数。

### 3. 确认与计算衔接

沿用 Excel 理解插件保存原件和证据，业务状态及读取、草稿更新、Boundary 推荐能力放在现有 MCHE 插件中。页面和 Agent 共用服务，用户确认接口不向模型开放。

保存需求核对状态及当前模式的输入齐备状态。确认前展示与当前计算草稿的差异；用户确认后原子更新当前草稿，保存需求及来源快照，使旧计算确认和准备包失效。拒绝跨会话、过期版本和并发修改后的提交。

当前后端仅支持 PTM。其他模式可填写和确认，但明确阻塞执行，不能沿用旧 PTM 参数包。部件选型和工程核对继续独立确认；本期不扩展真实 DLL 模式。

### 4. 实施与验收

按“字段与模式清单核对→草稿及推荐服务→右侧填写与计算衔接→验证”实施。

验证模板识别、26 条有值记录及空白排除、小数逗号、百分比、零、绝压、疑问标记和单位依据；验证模式切换、单次唯一输入、未接入模式阻塞、刷新恢复、确认失效和会话隔离。

完成浏览器交互及现有 Excel、选型、计算准备流程回归；原 Excel 保持不变，未完成的环境验证单独记录。
